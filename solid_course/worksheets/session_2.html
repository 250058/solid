class Bird(ABC):
    """fly(altitude) 의 약속
        - 받는 조건  : altitude 는 0보다 큰 정수이면 된다.
        - 끝난 뒤 보장: 호출이 끝나면 self.altitude == altitude 이다.
        - 항상 참    : self.altitude 는 언제나 0 이상이다."""
    def __init__(self, name): self.name = name; self.altitude = 0
    @abstractmethod
    def fly(self, altitude: int) -> None: ...

class Sparrow(Bird):
    def fly(self, altitude): self.altitude = altitude; print(...)

class Eagle(Bird):
    def fly(self, altitude): print("날개를 활짝 편다"); self.altitude = altitude; print(...)

class Penguin(Bird):
    def fly(self, altitude): print("(뒤뚱뒤뚱 걷기만 한다)")   # 날 수 없으니 그냥 넘어간다

class RubberDuckToy(Bird):          # 오리 모양 장난감 드론
    def fly(self, altitude):
        if altitude <= 10:
            raise ValueError("장난감 드론은 10m보다 높게만 뜰 수 있어요")
        self.altitude = altitude

def launch_all(birds: list[Bird], altitude: int = 5):
    for bird in birds:
        bird.fly(altitude)          # 예외가 나면 잡아서 기록한다
        # 끝난 뒤 bird.altitude 를 보고 "약속 지킴 / 약속 깨짐" 을 출력한다

리스코프 치환 원칙 (LSP, Liskov Substitution Principle)

상위 타입을 쓰는 코드는, 그 자리에 어떤 하위 타입을 넣어도 상위 타입이 약속한 그대로 올바르게 동작해야 한다. 상속 문법이나 메서드 이름이 같은 것만으로는 부족하고, 행동이 약속을 지켜야 한다.

계약: 사전조건 · 사후조건 · 불변식

  • 사전조건: 호출하는 쪽이 지켜야 하는 입력 조건. 하위 타입은 이것을 더 좁히면(강화) 안 된다. 넓히는 것은 괜찮다.
  • 사후조건: 호출이 끝난 뒤 보장되는 결과. 하위 타입은 이것을 덜 지키면(약화) 안 된다. 더 보장하는 것은 괜찮다.
  • 불변식: 객체에서 언제나 성립해야 하는 성질. 하위 타입도 유지해야 한다.

인터페이스 분리 원칙 (ISP, Interface Segregation Principle)

클라이언트는 자신이 쓰지 않는 메서드에 의존하도록 강요받아서는 안 된다. 큰 인터페이스는 쓰는 쪽(클라이언트)이 함께 쓰는 묶음 기준으로 나눈다. 메서드 하나마다 인터페이스를 만들라는 뜻이 아니다.

파이썬 Protocol

typing.Protocol은 "이런 메서드를 가진 것"이라는 약속을 정의한다. 클래스가 Protocol을 상속하지 않아도 메서드 모양이 맞으면 그 약속을 지킨 것으로 본다(구조적 타이핑). 실행 중 isinstance로 검사하려면 @runtime_checkable이 필요하다.
